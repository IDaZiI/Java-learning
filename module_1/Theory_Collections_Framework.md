# 1. Collections Framework

**Collections Framework** — набор интерфейсов и реализаций Java для работы с группами объектов.

Основные абстракции:

```text
Collection
├── List
├── Set
└── Queue / Deque

Map  ← отдельная иерархия
```

Важно: **Map** не наследуется от Collection.

## 2. Collection

`Collection<E>` — базовый интерфейс для большинства коллекций, которые хранят набор отдельных элементов.

Он задаёт общие операции:

```java
    add(E element)
    remove(Object element)
    contains(Object element)
    size()
    isEmpty()
    clear()
```

Например:

```java
Collection<String> names = new ArrayList<>();

names.add("Alex");
names.add("Bob");

System.out.println(names.size());
```

Но Collection сама по себе не определяет:

- есть ли порядок;
- разрешены ли дубликаты;
- как именно хранятся элементы.

Это уже определяется конкретными подинтерфейсами.

## 3. List

`List<E>` — коллекция, которая:

- сохраняет порядок элементов;
- допускает дубликаты;
- имеет индексы;
- позволяет обращаться к элементу по индексу.

```java
List<String> names = new ArrayList<>();

names.add("Alex");
names.add("Bob");
names.add("Alex");
```

Получаем:

```text
index:  0       1       2
       Alex    Bob     Alex
```

Дубликаты разрешены.

### 3.1. Основные операции List

| Операция              | Назначение                        | Пример                     |
| --------------------- | --------------------------------- | -------------------------- |
| `add(E)`              | Добавить элемент в конец          | `list.add("Alex")`         |
| `add(int, E)`         | Добавить элемент по индексу       | `list.add(2, "Alex")`      |
| `get(int)`            | Получить элемент по индексу       | `list.get(2)`              |
| `set(int, E)`         | Заменить элемент по индексу       | `list.set(2, "Alex")`      |
| `remove(int)`         | Удалить элемент по индексу        | `list.remove(2)`           |
| `remove(Object)`      | Удалить первое вхождение объекта  | `list.remove("Alex")`      |
| `contains(Object)`    | Проверить наличие элемента        | `list.contains("Alex")`    |
| `indexOf(Object)`     | Найти индекс первого вхождения    | `list.indexOf("Alex")`     |
| `lastIndexOf(Object)` | Найти индекс последнего вхождения | `list.lastIndexOf("Alex")` |
| `size()`              | Получить количество элементов     | `list.size()`              |
| `isEmpty()`           | Проверить, пуст ли список         | `list.isEmpty()`           |
| `clear()`             | Удалить все элементы              | `list.clear()`             |

### 3.2. List и интерфейсная абстракция

Предпочтительный стиль:

```java
List<String> names = new ArrayList<>();
```

а не обязательно:

```java
ArrayList<String> names = new ArrayList<>();
```

Потому что:

```text
List                 ← что нам нужно
  ↑
ArrayList             ← как реализовано
```

Это называется programming to an interface.

Мы зависим от контракта List, а не от конкретной реализации.

Поэтому реализацию можно заменить:

```java
List<String> names = new ArrayList<>();
```

на:

```java
List<String> names = new LinkedList<>();
```

при условии, что используемый код опирается только на возможности List.

Главный принцип:

> Слева — что нам нужно, справа — конкретная реализация.

### 3.3. Основные реализации List

#### 3.3.1. ArrayList

Внутри использует динамически расширяемый массив.

`[A][B][C][D][ ][ ]`

Главные преимущества:

- быстрый доступ по индексу;
- хорошая cache locality;
- компактное хранение;
- обычно хороший выбор по умолчанию для List.

#### 3.3.2. LinkedList

Основан на двусвязных узлах:

`[A] ⇄ [B] ⇄ [C] ⇄ [D]`

Каждый Node содержит примерно:

```text
item
next
prev
```

Особенности:

- get(index) → O(n)
- операции с концами → O(1)
- изменение связей уже найденного узла → O(1)

Недостатки:

- отдельные Node;
- больше памяти;
- хуже cache locality;
- произвольный доступ по индексу медленный.

#### 3.4. ArrayList vs LinkedList

| Операция                |          ArrayList | LinkedList |
| ----------------------- | -----------------: | ---------: |
| `get(index)`            |           **O(1)** |   **O(n)** |
| `set(index)`            |           **O(1)** |   **O(n)** |
| `add()` в конец         | amortized **O(1)** |   **O(1)** |
| `add(0, x)`             |           **O(n)** |   **O(1)** |
| `remove(0)`             |           **O(n)** |   **O(1)** |
| Последовательный проход |           **O(n)** |   **O(n)** |
| Cache locality          |            хорошая |     плохая |
| Дополнительные `Node`   |                нет |         да |

Но:

> Big O — не всё.

ArrayList часто выигрывает на практике благодаря последовательному расположению данных в памяти и меньшему количеству объектов.
