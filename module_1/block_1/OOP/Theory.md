# Углубленная Java

## Блок 1. ООП

### 1. Объекты

> Класс — это описание.
> Объект — это конкретный экземпляр в памяти.

Пример *класса*:

``` java
class Cat {
    String name;
    int age;
}
```

Пример *объекта*:

``` java
Cat cat = new Cat();
```

**ВАЖНО**: new создает новый объект в памяти (или же в heap/куче)

И переменная *cat* не хранит объект, она хранит ссылку на объект. Т.е. переменная cat хранит только адрес, где лежит переменная.

Еще одна **ВАЖНОСТЬ**:

``` java
Cat cat1 = new Cat();

Cat cat2 = cat1;
```

Тут только **ОДИН** объект. Обе переменные указывают на один объект.

Т.е. если мы сделаем вот так:

``` java
cat1.name = "Barsik";

System.out.println(cat2.name);
```

Вывод будет: `Barsik`

---

#### Немного о памяти

``` java
+----------------------+
| Stack                |
|                      |
| cat ------------+    |
+-----------------|----+
                  |
                  v
+----------------------+
| Heap                 |
|                      |
| Cat                  |
| name = "Barsik"      |
| age = 2              |
+----------------------+
```

Кто и что хранит:

| Стек | Куча |
| --------- | --------- |
| локальные переменные, ссылки, параметры метода | все объекты |

В Java переменные объектных типов хранят ссылки, а не сами объекты.

Присваивание объекта переменной **НЕ копирует объект**. Оно копирует только ссылку.

### 2. Конструкторы

> Конструктор — специальный член класса, который вызывается автоматически при создании объекта с помощью new и используется для его инициализации.

#### 2.1. Особенности конструктора

Конструктор похож на метод, но есть три отличия:

1. имя конструктора совпадает с именем класса;
2. конструктор не имеет возвращаемого типа, даже void;
3. вызывается автоматически при использовании new;
4. у класса может быть несколько конструкторов;
5. конструкторы могут быть перегружены.

#### 2.2. Конструктор по умолчанию

Если в классе не объявлен ни один конструктор, компилятор автоматически предоставляет конструктор без параметров.
Но если объявить хотя бы один собственный конструктор, автоматический конструктор без параметров больше не создается.

#### 2.3. Перегрузка конструкторов

В одном классе можно иметь несколько конструкторов с разными сигнатурами:

``` java
Dog()
Dog(String)
Dog(String, int)
```

Название параметров при определении сигнатуры не учитывается.

---

### 2.4. this

> this обозначает текущий объект.

``` java
this.name = name;
```

Здесь:

- this.name — поле текущего объекта;
- name — параметр метода/конструктора.

#### 2.5. this()

> this(...) используется для вызова другого конструктора этого же класса.

``` java
public Dog() {
    this("Unknown", 0);
}

public Dog(String name, int age) {
    this.name = name;
    this.age = age;
}
```

Важно:

- this(...) **не создает** новый объект;
- вызывается конструктор того же объекта;
- this(...) должен быть **первой** инструкцией конструктора.

**Главное правило:**

- new → создает объект → запускается конструктор
- this(...) → не создает объект → вызывает другой конструктор

### 3. Инкапсуляция

> Инкапсуляция — принцип ООП, согласно которому внутреннее состояние объекта скрывается от прямого внешнего доступа, а взаимодействие с объектом происходит через определенный публичный интерфейс.

Главная идея: **Объект сам контролирует свое состояние.**

#### 3.1. Модификаторы доступа

В Java есть четыре уровня доступа:

| Модификатор      | Доступ                       |
| ---------------- | ---------------------------- |
| `public`         | отовсюду                     |
| `protected`      | тот же пакет + наследники    |
| без модификатора | только внутри того же пакета |
| `private`        | только внутри самого класса  |

#### 3.2. private

Если поле объявлено как private:

``` java
private String name;
```

обратиться к нему напрямую из другого класса нельзя:

``` java
dog.name = "Бобик"; // ошибка
```

Поле доступно только внутри Dog.

#### 3.3. public

public позволяет обращаться к члену класса извне:

``` java
public void bark() {
    System.out.println("Гав!");
}
```

Другой класс может вызвать:

``` java
dog.bark();
```

#### 3.4. Геттеры и сеттеры

Для контролируемого доступа к private полям часто используются методы.

> Getter — получает значение.

``` java
public String getName() {
    return name;
}
```

> Setter — изменяет значение.

``` java
public void setName(String name) {
    this.name = name;
}
```

#### **Зачем нужна инкапсуляция?**

Она позволяет:

- защищать состояние объекта;
- контролировать изменение данных;
- проверять входные значения;
- скрывать внутреннюю реализацию;
- изменять внутреннюю реализацию, не ломая код пользователей класса.

Инкапсуляция — это не просто private + getter/setter. Это распространенное упрощение.
> Класс должен сам отвечать за корректность своего состояния.

### 4. Final

> «Это нельзя изменить определенным образом после того, как оно было установлено».

final может быть у:

- переменной;
- поля;
- параметра метода;
- метода;
- класса.

#### 4.1. final переменная

``` java
final int age = 20;
```

означает:
> переменной age нельзя присвоить другое значение после её инициализации.

Например:

``` java
final int x;

x = 10; // OK

x = 20; // ошибка
```

**ВАЖНО:** final переменная не обязана получать значение прямо при объявлении.

Если Java сможет гарантированно определить, что x получит значение ровно один раз, это допустимо. Пример:

``` java
final int x;

if (someCondition) {
    x = 10;
} else {
    x = 20;
}
```

#### 4.2. final и объекты

``` java
final Cat cat = new Cat();

cat = new Cat(); // НЕЛЬЗЯ
```

Но можно сделать так:

``` java
сat.name = "Barsik";
```

ПОТОМУ ЧТО, final у объекта запрещает изменить ссылку, а не сам объект.

> final у ссылочной переменной запрещает переназначить ссылку, но не делает сам объект неизменяемым.

``` java
final Cat cat = new Cat();

cat.name = "Barsik"; // допустимо

cat = new Cat();     // ошибка
```

#### 4.3. final поле

``` java
class BankAccount {

    private final String owner;
    private double balance;

}
```

После того как owner получил значение, изменить его больше нельзя.
Это очень полезно для данных, которые должны быть неизменяемыми.

Т.е. кодом сверху мы даем знать Java, что «После создания счета владелец этого счета больше не меняется».

#### 4.4. final параметр метода

``` java
public void deposit(final double amount) {
    // ...
}
```

Теперь внутри метода нельзя сделать: `amount = 100;`

#### 4.5. Константы

`public static final int MAX_AGE = 120;`

Здесь сразу три слова:

1. public — доступ отовсюду;
2. static — принадлежит классу, а не конкретному объекту;
3. final — нельзя изменить после инициализации.

Такие значения обычно называют константами. По соглашению Java их пишут:

`UPPER_SNAKE_CASE`

#### 4.6. Очень важное различие

|final переменная|final у объекта|
|---|---|
|`final int x = 10;`|`final Cat cat = new Cat();`|
|x = 10|cat ───────→ Cat object|
|изменить значение нельзя.|Нельзя изменить саму ссылку, но можно изменить объект|
|x = 20 // ❌|cat = new Cat(); // ❌|
||cat.name = "Barsik"; // ✅|

КРАТКАЯ СВОДКА:

final **запрещает** повторное присваивание переменной.

Для примитивной **переменной** это означает, что её значение **нельзя** изменить.

Для **ссылочной** переменной final запрещает изменить **ссылку** на другой объект, но не делает сам объект **неизменяемым**.

final поле часто используется, чтобы гарантировать, что определенная часть состояния объекта задается **один раз и больше не меняется**.

#### 4.7. final у методов и классов

> final может запрещать дальнейшее изменение поведения класса через наследование.

#### 4.7.1. final метод

``` java
class Animal {

    public final void breathe() {
        System.out.println("Дышит");
    }
}
```

У нас есть класс Animal.
Позже мы создадим наследника:

`class Dog extends Animal {}`

Dog автоматически получает метод `breathe()`.

Но вот так сделать **нельзя**:

``` java
class Dog extends Animal {

    @Override
    public void breathe() {
        System.out.println("Собака дышит");
    }
}
```

Будет ошибка компиляции. Потому что метод объявлен final, что означает:

> final метод значит, что этот метод нельзя переопределить в классе-наследнике.

#### 4.7.2. final класс

Можно запретить само наследование класса:
`final class BankAccount {}`

И теперь `class SpecialBankAccount extends BankAccount {}` нельзя. Компилятор выдаст ошибку.

> final класс значит, что От этого класса нельзя наследоваться.

#### 4.8. Три значения final

|final переменная|final метод|final класс|
|---|---|---|
|Запрещает повторное присваивание.|Запрещает переопределение.|Запрещает наследование.|

### 5. Наследование

> Наследование — механизм ООП, позволяющий создать новый класс на основе существующего и получить его доступные поля и методы.

#### 5.1. Основной синтаксис

``` java
class Animal {
    String name;

    void eat() {
        System.out.println("Животное ест");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Гав!");
    }
}
```

`Animal` — *родительский класс / суперкласс*.

`Dog` — *дочерний класс / подкласс / наследник*.

extends устанавливает отношение наследования:

> Dog IS-A Animal

То есть Dog является Animal.

#### 5.2. Что получает наследник

``` java
Dog dog = new Dog();

dog.name;    // поле Animal
dog.eat();   // метод Animal
dog.bark();  // метод Dog
```

Наследник получает доступные ему члены родительского класса и может добавлять собственные.

**extends не означает простое копирование кода из одного класса в другой.**

Это отношение между классами. `Dog dog = new Dog();` создаётся один объект `Dog`, а не отдельные `Animal` и `Dog`.

#### 5.3. super

``` java
class Animal {

    String name;

    Animal(String name) {
        this.name = name;
    }
}

class Dog extends Animal {

    Dog(String name) {
        // Что здесь происходит?
    }
}
```

Если мы создаём `Dog`, а у `Animal` есть собственный конструктор, как Java должна инициализировать часть объекта, относящуюся к `Animal`?

Например: `this(...)` вызывает *другой конструктор этого же класса*.

А `super(...)` вызывает *конструктор родительского класса*.

Простой пример:

``` java
class Animal {

    String name;

    Animal(String name) {
        this.name = name;
    }
}

// Наследник

class Dog extends Animal {

    Dog(String name) {
        super(name);
    }
}
```

Упрощённо цепочка выглядит так:

``` java
new Dog("Bobik")
       ↓
Dog(...)
       ↓
super("Bobik")
       ↓
Animal("Bobik")
       ↓
this.name = "Bobik"
```

Также `this(...)` и `super(...)` должны находиться **первой** инструкцией конструктора.

Коротко о главном:

> super(...) вызывает конструктор родительского класса.

``` java
class Dog extends Animal {


    Dog(String name) {
        super(name);
    }
}
```

- super(...) вызывает конструктор родителя;
- super() — конструктор родителя без параметров;
- super(...) должен быть первой инструкцией конструктора;
- если явно не написать super(...), Java пытается вставить super() автоматически;
- если у родителя нет конструктора без параметров, необходимо явно вызвать подходящий конструктор через super(...);
- super.method() позволяет вызвать реализацию метода родительского класса.
- Автоматический super() вставляется только тогда, когда конструктор не содержит явного вызова this(...) или super(...).

### 6. Переопределение методов (@Override)

> Переопределение (override) — создание в классе-наследнике собственной реализации унаследованного метода с той же сигнатурой.

``` java
class Animal {
    void sound() {
    }
}

class Dog extends Animal {

    @Override
    void sound() {
    }
}
```

`@Override` сообщает компилятору, что метод должен переопределять метод родителя.

Не путать:

- Переопределение, Override → наследование + одинаковая сигнатура. Пример: `@Override void eat()`
- Перегрузка, Overload → один класс/иерархия + разные параметры. Пример: `void eat() {}, void eat(String food){}`

Для:

`Animal animal = new Dog();`

важно различать:

- тип переменной → Animal;
- реальный тип объекта → Dog.

Какие методы доступны для вызова — определяется типом переменной.

> Какая реализация переопределённого метода будет выполнена — определяется реальным типом объекта.

### 7. Полиморфизм

> Полиморфизм — возможность работать с объектами разных классов через общий тип, при этом вызывая реализацию, соответствующую реальному типу объекта.

Например:

``` java
Payment payment = new CardPayment();
payment.pay(100);
```

Тип переменной: `Payment`

Реальный тип объекта: `CardPayment`

Поэтому вызывается: `CardPayment.pay()`

Главное правило:

**Тип переменной определяет доступные методы. Реальный тип объекта определяет реализацию переопределённого метода.**

### 8. Абстрактные классы

> Абстрактный класс — класс, предназначенный для использования в качестве основы для наследников. Нельзя создать его экземпляр напрямую.

``` java
abstract class Animal {
}
```

`new Animal(); // ❌`

`Animal animal = new Dog(); // ✅`

> Абстрактный метод — метод без реализации, который должен быть реализован конкретным наследником.

`abstract void sound();`

Конкретный наследник:

``` java
@Override
void sound() {
    System.out.println("Гав!");
}
```

**Важно:**

- абстрактный класс может иметь обычные методы;
- абстрактный класс может иметь поля;
- абстрактный класс может иметь конструкторы;
- обычный наследник обязан реализовать все абстрактные методы;
- абстрактный наследник может оставить их нереализованными;
- abstract и final вместе использовать нельзя.

> Абстрактный класс не просто запрещает создание объекта. Он позволяет выразить намерение дизайна: "это общая основа, а конкретное поведение должны определить наследники".

Java *запрещает* множественное наследование классов.

То есть у класса может быть только *один* superclass.

### 9. Интерфейсы

> Интерфейс — контракт, определяющий поведение, которому должен соответствовать класс.

```java
interface Flyable {

    void fly();
}
```

Класс реализует интерфейс через implements:

``` java
class Bird implements Flyable {

    @Override
    public void fly() {
        System.out.println("Птица летит");
    }
}
```

**extends (наследование):**

- устанавливает наследование между классами;
- класс может иметь только одного непосредственного родителя;
- отношение: IS-A.

**implements (интерфейс):**

- означает реализацию интерфейса;
- класс может реализовывать несколько интерфейсов;
- описывает способность/контракт: CAN-DO.

Например: `class Bird extends Animal implements Flyable, Runnable {}`

Bird:

- является Animal;
- умеет Flyable;
- умеет Runnable.

Интерфейс также может использоваться как тип: `Flyable flyable = new Bird();`

Какие методы можно вызвать, определяется типом переменной:

``` java
flyable.fly();        // ✅
flyable.makeSound();  // ❌ если makeSound() нет в Flyable
```
